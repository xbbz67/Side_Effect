# Responsive behavior

**PROPOSED DIGITAL UX**; desktop first, with readability preserved through different compositions.

| Viewport | Layout | Information policy |
|---|---|---|
| 1920×1080 | Full 320px rail, adaptive opposing seats, local Psyche and hand bands | All names/statuses visible, full art on inspection |
| 1440×900 | 280px rail; opponent summaries in top grid; own Psyche wraps into two rows if needed | All conditions enumerated; wider focused target drawer |
| 1280×720 | History collapsed to drawer; current action remains pinned; own hand rack rather than deep fan | One expanded opponent, other summaries keep names/status counts |
| Narrow tablet | Stacked opponent summaries, pinned active chooser/action, own Psyche grid, horizontal hand | Tap detail drawer and target list replace hover/drag |
| Phone / portrait | Lobby and rules supported; gameplay uses explicit opponent list and selected-board panel | Not claimed polished in first desktop phase; full accessible interaction still required if advertised |

At 200% zoom, use the narrow composition rather than clipping cards behind panels. Horizontal scrolling is acceptable inside an owned hand rack, not for the whole table or mandatory action controls. Keep cards represented as content, not fixed absolute text boxes that become unreadable when shrunk.

Long names, multiple simultaneous restriction badges, eight Disorder slots, 12+ hand cards through gifts, large localized text, slow networks, and screen-reader order are acceptance fixtures. Selecting an enemy condition must never require pixel-perfect placement on a tiny overlapping illustration.

Seat summaries always expose current status; opening details must not send hidden card data. Spectators use the same public composition with no local hand and a persistent spectator label.
